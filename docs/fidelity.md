# Fidelity rules and limits

Ferry keeps the captured source byte-for-byte, but cross-provider output is a projection, not a lossless migration. This page records exactly what conversions preserve, what they report as lost, and how each format was verified.

## Fidelity rules

- Tool identity is preserved: Codex MCP namespaces survive round trips and render as one `mcp__server__tool` name for Claude and Gemini. Codex free-text custom tool input (`custom_tool_call`) is wrapped as `{"input":"..."}` for object-only targets and reported.
- Tool outcomes are preserved: Claude's `is_error`, OpenCode's error status, and Gemini's error status map to each other; Codex's observed rollout format has no error flag, so the flag is reported as dropped instead of invented, and Codex readers still honor the flag in older development snapshots. When a tool call's status and its result flag disagree, the Gemini projection follows the result and reports the status change. Structured tool results are serialized as exact JSON text for text-only targets and reported; Gemini and Pi carry them as JSON natively.
- ACP alignment is intentionally limited to the canonical tool-call status field (`pending`, `in_progress`, `completed`, or `failed`) when a source carries a status with that meaning. Codex, Gemini, and OpenCode readers populate it; provider-specific or unknown values remain in the original block. Writers do not claim to emit ACP status unless the target has a verified native representation, and conversions report any status loss. Ferry does not implement ACP's JSON-RPC transport.
- Numbers stay exact: tool arguments and results never pass through float64, so integers above 2^53 survive writes, read-backs, and projection checks.
- Records with no cross-provider representation are counted in `Transfer.Limitations`, never dropped silently: Codex developer/system role messages, Codex thinking blocks, compacted `replacement_history` payloads, Gemini model thoughts, Trae CLI state/event records, Trae reasoning-marked text blocks, empty Pi messages, Qoder meta messages, dsh reasoning blocks and unknown events, Qwen thought blocks and compression summaries and branch forks, Copilot skill-context blocks and sub-agent sidechains, and Pi inactive branches or provider-only records. Claude top-level `summary` records join the messages like Codex compaction records.
- The newer providers follow their reference formats: Qoder records form a parent-linked chain that fails closed on branches, and its workspace lives in an optional sidecar the JSONL stream cannot carry. dsh streamed text deltas are assembled into messages, and a persisted assistant message supersedes its deltas; zstd-framed logs decode transparently while the captured original stays the exact compressed file. Qwen `thought` parts and compression summaries are counted rather than guessed; Copilot skill-context blocks are stripped from user text and counted. Copilot has no tool-error flag, so a source error flag is reported as dropped.
- Trae re-injects AGENTS.md instructions and environment context itself and drops user records consisting only of such envelopes on read-back, so conversions to Trae skip them and report the removal.
- Timestamps are validated: a conversion may fill in a missing message time, but it may never change one that the source carried. OpenCode stores times at millisecond precision; truncating finer precision is reported rather than failing the conversion.
- Gemini replay semantics follow the official history service: `$set {"messages":null}` does not clear a session.
- Writers validate the complete document before emitting output. Codex output requires a UUID native ID, an absolute workspace, and an RFC 3339 timestamp; `Convert` derives a stable RFC 4122 version 5 UUID from the source identity when the source uses another scheme and reports the derivation. OpenCode output requires a native ID, a workspace, and message timestamps; an unfinished tool call, or a result separated from its call by other content, is rejected rather than reordered. Claude base64 and URL image blocks convert to Codex `input_image` blocks and back, with unsupported metadata rejected rather than dropped; Gemini supports its text, tool, and inline/file image subset and requires a native ID, an absolute workspace to compute its project hash, timestamps, known tool status, and enough source metadata for function responses. Codex compacted summaries read and write as Codex records; Claude, Gemini, and OpenCode have no verified equivalent and reject summary messages.

## Verification levels

The Qoder codec follows the parent-linked chain layout of earlier Qoder CLI releases and is covered by codec and public integration tests; newer Qoder CLI releases have moved to a different, Claude Code-shaped record layout that Ferry does not parse yet. The DeepSeek Harness, Qwen Code, and Copilot CLI formats follow the MIT-licensed [deja-vu](https://github.com/vshulcz/deja-vu) reference parsers and are covered by codec and integration tests, but no native CLI verification exists on this machine; treat their coverage as reference-derived. dsh logs default to zstd framing, which Ferry decodes; raw-line logs restore equally byte-exactly.

## Limits

The captured source restores byte-for-byte, but cross-provider output is a projection, not lossless migration. `Convert` keeps the original snapshot beside the target, reads the target back, and validates supported content, session identity, workspace, and timestamps; everything it could not represent is listed in `Limitations`. OpenCode storage sessions span many files, so their captured original is a `{"path","data"}` archive rather than one native stream; `RestoreOriginal` reproduces that archive exactly. OpenCode progress parts (step markers, reasoning), Gemini replay/patch records, Trae CLI state/event records, and Pi inactive branches or provider-only records stay in the original only. Gemini output stores a project hash derived from the source workspace, so target read-back cannot recover that workspace; a Gemini source without a workspace cannot be converted to Codex without inventing one. Codex archived rollouts compressed as `.jsonl.zst` are not discovered. Compacted histories, branch reconstruction, and provider-specific metadata are not fully portable. A cross-provider conversion requires at least one supported message; use the original snapshot for source-only or unsupported sessions.

Earlier development snapshots derived nonstandard IDs for non-UUID source sessions; the corrected UUID v5 derivation changes those generated target IDs. Previously written target sessions keep their existing IDs.

## Native checks

The native Codex smoke test, [`scripts/native-codex-smoke-test.sh`](../scripts/native-codex-smoke-test.sh), converts a synthetic Claude session and asks the installed Codex CLI to migrate the generated rollout with `codex migrate-rollouts`. It verifies that the CLI recognizes and processes the file; it does not start a turn or prove that the migrated session can be resumed with full semantic fidelity. Generated files should not be placed in an agent's session directory based on this check alone.

The native Gemini smoke test, [`scripts/native-gemini-smoke-test.sh`](../scripts/native-gemini-smoke-test.sh), writes a synthetic Gemini session and asks the installed Gemini CLI to list it from an isolated session store. It verifies discovery of the generated file; it does not start a model turn or prove native resume. The direct Gemini codec tests in `session/gemini_test.go` cover the writer and reader's supported format subset; the public Parse/Discover/Convert coverage is in `session/gemini_integration_test.go`, including cross-provider projection and source snapshot behavior.

The native Claude smoke test, [`scripts/native-claude-smoke-test.sh`](../scripts/native-claude-smoke-test.sh), converts a synthetic Codex session into Claude format, places it in an isolated `CLAUDE_CONFIG_DIR` project directory, and asks the installed Claude CLI to resume it without a prompt. The CLI exits before starting a turn; a session it discovers and parses produces its parsed-transcript complaint, while a missing or unparseable file produces `No conversation found`. The test asserts that difference. It verifies discovery and parsing, not a continued conversation.

The native OpenCode smoke test, [`scripts/native-opencode-smoke-test.sh`](../scripts/native-opencode-smoke-test.sh), converts a synthetic Claude session (text, a successful call, and a failed result) and asks the installed OpenCode CLI to import it, list it, and re-export it from an isolated `XDG_DATA_HOME`. It verifies that the CLI accepts the generated document, including error-status tool results; it does not start a model turn or prove native resume.

Trae and Pi are covered by codec and public integration tests. Ferry reads Trae CLI rollouts from `~/.trae/cli/sessions` and `~/.trae/cli/archived_sessions`, and Pi sessions from `~/.pi/agent/sessions`. The optional `scripts/native-trae-smoke-test.sh` verifies that the installed Trae CLI identifies a generated rollout as eligible for migration; `scripts/native-pi-smoke-test.sh` checks that Pi exports a generated session offline. Neither check proves that a model can continue the session or that every source record is interpreted correctly.

The format handling and discovery are inspired by the MIT-licensed [agentsview](https://github.com/kenn-io/agentsview) and [deja-vu](https://github.com/vshulcz/deja-vu) projects. This implementation is independently written; it does not claim equivalent coverage. The OpenCode import schema was confirmed against CLI 1.18.32. Fixtures are synthetic examples based on observed formats.
